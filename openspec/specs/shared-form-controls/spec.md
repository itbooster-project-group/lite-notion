# shared-form-controls Specification

## Purpose

Предоставить формам приложения единый публичный набор доступных контролов с согласованными состояниями, типами значений и предсказуемым управлением с клавиатуры.

## Requirements

### Requirement: Публичный контракт контролов

UIKit SHALL предоставлять Button, Input, Label, Textarea, Checkbox, Select и их именованные публичные типы через `@/shared/ui`, без необходимости импортировать внутренние модули. Существующие вызовы Button и Input SHALL сохранять совместимость, включая ref, атрибуты доступности и композицию Button через render.

#### Scenario: Использование публичного API
- **WHEN** потребитель импортирует шесть компонентов и их props-типы через `@/shared/ui`
- **THEN** импорт и типизация проходят без обращения к внутренним библиотечным путям

#### Scenario: Совместимость существующих форм
- **WHEN** форма передаёт Input ref, name, onChange, onBlur и атрибуты доступности, а Button использует существующие variant, size или render
- **THEN** соответствующие обработчики, фокусировка и семантика сохраняются

### Requirement: Согласованные размеры и состояния

UIKit SHALL сохранять текущие variants и размеры Button. Input и Select SHALL поддерживать визуальные размеры sm/default/lg с высотами 24/28/32 px; Textarea SHALL использовать соответствующие отступы и rows для высоты. Input SHALL сохранять нативный атрибут size отдельно от визуального размера. Label и Checkbox SHALL иметь один базовый размер. Поля SHALL поддерживать disabled и error через aria-invalid; пустое значение само по себе SHALL NOT означать ошибку.

#### Scenario: Поле с ошибкой
- **WHEN** Input, Textarea, Checkbox или Select получает aria-invalid и aria-describedby, указывающий на текст ошибки
- **THEN** контрол визуально обозначает ошибку и сохраняет доступное описание без дублирования текста

#### Scenario: Запрещённое взаимодействие
- **WHEN** потребитель устанавливает disabled, в том числе вследствие отсутствия разрешения на действие
- **THEN** пользователь не может изменить значение или активировать действие мышью и клавиатурой
- **AND** контрол не принимает самостоятельных решений об авторизации

#### Scenario: Пустое поле
- **WHEN** Input или Textarea имеет пустое значение без aria-invalid
- **THEN** контрол сохраняет обычное состояние и показывает placeholder, если он задан

### Requirement: Загрузка и доступное имя Button

Button SHALL поддерживать loading с индикатором и aria-busy, сохранять доступное имя и блокировать повторную активацию и submit, включая композицию через render. Переход в loading SHALL сохранять фокус на уже сфокусированной кнопке, если одновременно не задан disabled. Иконки без текста SHALL получать доступное имя от потребителя; существующая подсказка для именованной icon-кнопки SHALL сохраняться вне disabled/loading.

#### Scenario: Повторная отправка
- **WHEN** пользователь кликает или нажимает Enter/Space на Button в loading
- **THEN** обработчик действия и отправка формы не выполняются повторно, доступное имя не заменяется индикатором

#### Scenario: Кнопка-ссылка при загрузке
- **WHEN** Button с render ссылки находится в loading
- **THEN** её активация не выполняет переход

### Requirement: Подписи и Checkbox

Label SHALL связываться с контролом через htmlFor. Checkbox SHALL поддерживать checked, unchecked, indeterminate, controlled и uncontrolled режимы, name/value и изменение с клавиатуры. Изменение Checkbox SHALL передавать boolean, а indeterminate SHALL задаваться отдельно.

#### Scenario: Активация подписи
- **WHEN** пользователь активирует Label, связанный с доступным Checkbox
- **THEN** Checkbox переключается и объявляет актуальное состояние

#### Scenario: Смешанное состояние
- **WHEN** Checkbox имеет indeterminate и пользователь переключает его клавишей Space
- **THEN** до переключения объявляется смешанное состояние, а обработчик получает новое boolean-значение

### Requirement: Режимы выбора Select

Select SHALL независимо поддерживать multiple и searchable, оба false по умолчанию. Одиночный режим SHALL использовать string или null, множественный — string[] без повторений; типы value, defaultValue и onValueChange SHALL соответствовать multiple. Оба режима SHALL поддерживать controlled/uncontrolled использование и disabled-варианты.

#### Scenario: Одиночный выбор
- **WHEN** пользователь выбирает доступный вариант в одиночном режиме с поиском или без него
- **THEN** значение обновляется, название отображается в триггере, список закрывается и фокус возвращается в триггер

#### Scenario: Множественный выбор
- **WHEN** пользователь выбирает или повторно выбирает вариант в multiple с поиском или без него
- **THEN** значение добавляется или удаляется, остальные выбранные значения сохраняются, список остаётся открытым
- **AND** триггер отображает до двух названий и количество остальных, а доступное описание включает все выбранные названия

#### Scenario: Недоступный вариант
- **WHEN** пользователь пытается выбрать disabled-вариант
- **THEN** значение и обработчик изменения остаются неизменными

#### Scenario: Очистка
- **WHEN** пользователь активирует доступную очистку при clearable=true и непустом выборе
- **THEN** значение становится null или [], уведомляется потребитель и фокус возвращается на триггер

### Requirement: Поиск и пустые состояния Select

При searchable=true Select SHALL фильтровать варианты локально по вхождению текста без учёта регистра. Фильтрация SHALL сохранять выбранные значения. Select SHALL различать отсутствие выбора, пустой исходный список и отсутствие результатов поиска; при каждом открытии запрос SHALL быть пустым.

#### Scenario: Фильтрация выбранных вариантов
- **WHEN** поисковый запрос скрывает выбранный вариант
- **THEN** выбор сохраняется и фильтрация сама по себе не вызывает onValueChange

#### Scenario: Пустые результаты
- **WHEN** исходный список пуст или поиск не находит совпадений
- **THEN** отображается соответственно «Нет доступных вариантов» или «Ничего не найдено», сообщение не является выбираемым вариантом

#### Scenario: Повторное открытие
- **WHEN** пользователь закрывает Select с запросом и открывает снова
- **THEN** запрос сброшен, выбранные значения сохранены

### Requirement: Клавиатура и интеграция форм

Select SHALL иметь доступное имя независимо от placeholder, сообщать состояние открытия и выбора, поддерживать открытие с клавиатуры, навигацию стрелками и выбор Enter. Escape SHALL закрывать список с возвратом фокуса на триггер, Tab SHALL позволять продолжить обход формы без ловушки фокуса. Поиск SHALL получать фокус при открытии searchable; без поиска активным SHALL становиться выбранный либо первый доступный вариант. Контролы SHALL работать внутри диалога и передавать актуальные значения в форму.

#### Scenario: Выбор в диалоге
- **WHEN** пользователь открывает Select внутри диалога, перемещается стрелками и нажимает Escape
- **THEN** закрывается список Select, диалог остаётся открытым и фокус возвращается на триггер

#### Scenario: Отправка и сброс формы
- **WHEN** форма читает именованные контролы или выполняет reset в uncontrolled-режиме
- **THEN** чтение возвращает актуальные значения, multiple передаёт отдельное значение на каждый выбор, reset восстанавливает defaultValue/defaultChecked
- **AND** controlled-значения остаются под управлением потребителя
