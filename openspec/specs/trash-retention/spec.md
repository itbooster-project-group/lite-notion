# trash-retention Specification

## Purpose

Определяет, как долго удалённые страницы и проекты остаются восстановимыми и что происходит с ними по истечении этого срока: мягкое удаление обратимо, но не вечно, и записи, пролежавшие в корзине дольше срока хранения, должны исчезать из базы без участия пользователя.

## Requirements

### Requirement: Срок хранения удалённых записей
Удалённая страница и удалённый проект MUST оставаться восстановимыми в течение фиксированного срока хранения, отсчитываемого от отметки времени их удаления. Срок хранения MUST быть единым для страниц и проектов и MUST составлять 30 дней.

Срок хранения MUST NOT задаваться клиентом и MUST NOT зависеть от пользователя. Восстановление MUST сбрасывать отсчёт: повторно удалённая запись MUST храниться заново от новой отметки времени удаления.

#### Scenario: Запись в пределах срока восстановима
- **WHEN** с момента удаления страницы или проекта прошло меньше срока хранения
- **THEN** запись возвращается чтением корзины и подлежит восстановлению

#### Scenario: Отсчёт начинается заново после повторного удаления
- **GIVEN** страница, удалённая, восстановленная и удалённая снова
- **THEN** срок хранения отсчитывается от последнего удаления, а не от первого

#### Scenario: Срок не принимается от клиента
- **WHEN** запрос удаления или восстановления содержит поле со сроком хранения или временем окончательного удаления
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не изменяет запись

### Requirement: Окончательная очистка по истечении срока хранения
Система MUST периодически и без участия пользователя безвозвратно удалять из хранилища записи, чья отметка времени удаления старше срока хранения.

Безвозвратное удаление страницы MUST уносить с собой её документ и всё её поддерево. Безвозвратное удаление проекта MUST уносить с собой все его страницы и их документы. После очистки записи MUST NOT возвращаться ни одной операцией чтения, включая чтение корзины, и MUST NOT подлежать восстановлению.

Очистка MUST NOT затрагивать записи без отметки удаления и записи, удалённые в пределах срока хранения.

#### Scenario: Просроченная запись удаляется безвозвратно
- **GIVEN** страница, удалённая раньше, чем срок хранения назад
- **WHEN** выполняется очередной запуск очистки
- **THEN** страница и её документ исчезают из хранилища
- **AND** последующее восстановление этой страницы отвечает `404`

#### Scenario: Просроченный проект уносит свои страницы
- **GIVEN** проект, удалённый раньше, чем срок хранения назад
- **WHEN** выполняется очередной запуск очистки
- **THEN** проект, все его страницы и их документы исчезают из хранилища

#### Scenario: Запись в пределах срока не трогается
- **GIVEN** страница, удалённая в пределах срока хранения
- **WHEN** выполняется очередной запуск очистки
- **THEN** страница остаётся в хранилище и по-прежнему возвращается чтением корзины

#### Scenario: Живые записи не трогаются
- **WHEN** выполняется очередной запуск очистки
- **THEN** ни одна запись без отметки удаления не исчезает из хранилища

#### Scenario: Восстановленная запись не удаляется
- **GIVEN** страница, восстановленная до истечения срока хранения
- **WHEN** выполняется очередной запуск очистки после того, как с момента её прежнего удаления прошло больше срока хранения
- **THEN** страница остаётся в хранилище и возвращается обычным чтением дерева

### Requirement: Срок хранения — верхняя граница, а не нижняя
Срок хранения MUST ограничивать время, в течение которого удалённая запись остаётся восстановимой, но MUST NOT задавать минимальное время её жизни в хранилище: пользователь MUST иметь возможность удалить содержимое своей корзины безвозвратно в любой момент до истечения срока.

Результат ручного окончательного удаления и результат истечения срока хранения MUST быть неотличимы: обе дороги MUST уносить одни и те же связанные записи и MUST делать запись невосстановимой.

Ни ручное окончательное удаление, ни истечение срока MUST NOT затрагивать записи, не помеченные удалёнными.

#### Scenario: Ручное удаление до истечения срока
- **GIVEN** страница, удалённая только что
- **WHEN** пользователь удаляет её из корзины безвозвратно, не дожидаясь истечения срока хранения
- **THEN** страница и её документ исчезают из хранилища, а её восстановление отвечает `404`

#### Scenario: Ручное и отложенное удаление дают одинаковый результат
- **WHEN** одна запись удалена безвозвратно вручную, а такая же другая — очередным запуском очистки по истечении срока
- **THEN** в обоих случаях из хранилища исчезает один и тот же набор связанных записей

#### Scenario: Очередной запуск очистки после ручного удаления
- **GIVEN** пользователь уже очистил свою корзину вручную
- **WHEN** выполняется очередной запуск очистки
- **THEN** запуск завершается без ошибки и не удаляет ни одной дополнительной записи

### Requirement: Устойчивость запланированной очистки
Очистка MUST быть идемпотентной: повторный запуск на тех же данных MUST давать тот же результат, а одновременный запуск на нескольких экземплярах приложения MUST NOT приводить ни к ошибке, ни к удалению записей в пределах срока хранения.

Недоступность базы данных в момент запуска MUST NOT ронять процесс приложения и MUST NOT отменять последующие запуски: очистка MUST повторить попытку в следующий по расписанию запуск. Отказ MUST фиксироваться в журнале без раскрытия параметров подключения.

#### Scenario: Повторный запуск на тех же данных
- **WHEN** очистка запускается дважды подряд без изменений данных между запусками
- **THEN** второй запуск не удаляет ни одной дополнительной записи и завершается без ошибки

#### Scenario: База недоступна
- **WHEN** очистка запускается при недоступной базе данных
- **THEN** процесс приложения продолжает работать, отказ попадает в журнал без параметров подключения
- **AND** следующий запуск по расписанию выполняется как обычно

#### Scenario: Параллельный запуск на нескольких экземплярах
- **WHEN** очистка запускается одновременно на нескольких экземплярах приложения
- **THEN** ни один запуск не завершается ошибкой, и ни одна запись в пределах срока хранения не удаляется
