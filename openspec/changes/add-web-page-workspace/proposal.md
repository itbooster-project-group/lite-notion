## Why

Backend уже публикует проекты и иерархические страницы, но web не показывает их как единое рабочее пространство. Приложению нужно одно дерево с проектами верхнего уровня и управлением страницами из навигации и выбранного проекта.

## Что меняется

- `/`, `/projects/[projectId]` и `/pages/[pageId]` используют один private workspace; URL страницы остаётся `/pages/[pageId]`.
- Боковая навигация становится единым деревом `проекты → страницы` вместо выбора проекта; проекты — верхние узлы.
- `/projects/[projectId]` показывает в контентной области редактируемое дерево выбранного проекта: создание, переименование, DnD мышью и клавиатурой и диалог перемещения.
- `/pages/[pageId]` показывает хлебные крошки, заголовок и заглушку редактора без запроса документа.
- Общие компоненты workspace используют сгенерированные shadcn-компоненты, а Steiger следует рекомендуемым правилам FSD без локальных отключений.
- Корневой маршрут показывает список всех проектов и компактную форму создания; создание корневой страницы переносится к названию проекта, а отступы дерева отражают каждый уровень вложенности.

Вне области изменения: backend/OpenAPI, переименование, удаление и перемещение проектов, удаление страниц, множественный выбор и редактор PageDocument.

## Возможности

### Новые возможности

- `web-page-workspace`: наблюдаемое поведение единого workspace, дерева проектов/страниц, маршрутов и операций над страницами.

### Изменённые возможности

Нет.

## Влияние

- `apps/web`: адаптеры маршрутов, экран/модель/тесты workspace, общие компоненты и FSD-структура.
- `steiger.config.js`: удаляются временные отключения правил; API и backend не меняются.
