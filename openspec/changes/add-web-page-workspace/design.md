## Контекст

Workspace получает проекты и общее дерево страниц текущего пользователя через сгенерированный клиент и TanStack Query. Backend поддерживает для проектов только получение списка и создание; API страниц сохраняет транспортный контракт.

## Цели и нецели

**Цели:** единое дерево проектов и страниц, полный набор действий со страницами из контента проекта, доступные маршруты и приведение FSD/shadcn в порядок.

**Не является целью:** изменения backend, PageDocument/редактора, мутации проектов и перемещение страниц между проектами.

## Решения

### 1. Одна модель дерева workspace

`pages/workspace/model` нормализует дерево страниц и строит Headless Tree с синтетическим корнем рабочей области. Его прямые потомки — виртуальные узлы проектов в порядке API, а потомки проектов — страницы в серверном порядке. Узлы проектов открывают маршрут проекта; перетаскивать и переименовывать можно только страницы. `/projects/{projectId}` использует тот же адаптер дерева с синтетическим корнем конкретного проекта: навигация и контент используют одни обработчики мутаций и общий query cache, но хранят состояние фокуса и раскрытия независимо.

### 2. Маршруты выбирают контекст представления

`WorkspaceRouteContext` содержит варианты `root`, `project` и `page`. Для корневого маршрута проект не выбран, маршрут проекта показывает дерево в контенте, а маршрут страницы — её заглушку. Маршрут страницы определяет проект по общему дереву; для недоступных идентификаторов используется единое безопасное состояние.

### 3. FSD использует рекомендованные правила без отключений

После удаления project hub проекции страниц и проектов имеют одного потребителя, поэтому находятся в `pages/workspace/model`, а не в entities. В `steiger.config.js` остаются рекомендованные правила и игнорирование generated/test-файлов без `fsd/insignificant-slice: off`.

### 4. Общие компоненты генерирует shadcn

`dialog`, `drawer`, `dropdown-menu` и `breadcrumb` добавляются CLI shadcn в настроенную папку `shared/ui/shadcn`; продуктовый код импортирует их через `shared/ui`. Самописные обёртки Base UI удаляются. Headless Tree остаётся локальным адаптером страницы, поскольку ему нужен иерархический DnD.

### 5. Мутации используют общее серверное состояние

Создание проекта обновляет кэш списка только после успеха. Создание страницы вставляет ответ в дерево страниц. Переименование и перемещение выполняют cancel → snapshot → optimistic transform → rollback → invalidate. Ошибки интерфейса остаются безопасными.

### 6. Компактное создание и ясная иерархия

`PageTree` получает отображаемый заголовок проекта и размещает рядом с ним иконку создания корневой страницы с доступным именем. Отдельная текстовая кнопка перед деревом не используется. Отступ строки рассчитывается напрямую по уровню Headless Tree, поэтому первый уровень не имеет отступа, а каждый дочерний — получает один шаг. Корневой маршрут показывает список проектов и форму создания; на широком экране элементы формы выстраиваются в строку. Название «Рабочая область» не используется как декоративный заголовок.

### 7. Открытие диалога после закрытия меню

Выбор «Переместить…» сохраняет запрос на открытие диалога, а сам `MovePageDialog` открывается из `onOpenChangeComplete(false)` меню действий. Поэтому меню успевает размонтировать портал до появления overlay диалога и завершающее pointer-событие не может немедленно закрыть диалог.

### 8. Неподвижный контент проекта и компактная мобильная навигация

Дерево в контенте проекта размещается от верхнего отступа без минимальной высоты и вертикального центрирования. На мобильном экране кнопка открытия навигации — иконка боковой панели в правом верхнем углу контента, без отдельной полосы и нижней границы. Drawer не показывает декоративный заголовок и описание, но содержит визуально скрытый заголовок для доступного имени диалога и icon-button закрытия с доступным именем.

### 9. Полноширинное содержимое приватного хедера

Внутренний контейнер хедера не ограничивается `max-w-shell` и не центрируется: логотип и профиль выравниваются по краям ширины viewport. Горизонтальные отступы `px-page-inline`, нижняя граница и адаптивное сокращение имени профиля сохраняются.

### 10. Компактный контент проекта и выход

Дерево проекта не сопровождается дублирующим поясняющим текстом. `LogoutButton` использует shadcn icon-button с иконкой выхода и доступным именем, которое отражает обычное и ожидающее состояние; обработка ошибки и блокировка кнопки сохраняются.

## Риски и компромиссы

- Два представления дерева могут расходиться по фокусу и раскрытию → хранить состояние представления локально, а данные получать из одного query cache.
- DnD мышью ограничен jsdom → тестировать преобразователи/адаптеры и выполнить browser smoke test.
- Steiger достигает лимита наблюдателей в этом окружении → использовать `CHOKIDAR_USEPOLLING=1` для проверки без отключения правил.

## План миграции

1. Синхронизировать маршруты, модель workspace и shadcn UI.
2. Удалить устаревшие hub/entities/обёртки и отключения Steiger.
3. Запустить тесты, проверку типов, сборку, линтер, Steiger и строгую валидацию; откат затрагивает только web-код, так как данные не меняются.
