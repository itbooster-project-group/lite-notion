## Why

Удаление страниц и проектов уже обратимо через API, но пользователь не может просмотреть корзину, восстановить элементы или управлять их окончательным удалением из интерфейса. Изменение предоставляет единый защищённый экран корзины, используя существующий backend lifecycle.

## What Changes

- Добавить доступный из боковой навигации защищённый маршрут `/trash` с отдельными вкладками страниц и проектов.
- Показывать удалённые элементы, дату удаления и контекст проекта/вложенности; обеспечить восстановление и индивидуальное безвозвратное удаление страниц и проектов.
- Подтверждать каждое необратимое удаление, включая отдельное подтверждение каскада после `409`.
- Обновлять обычные деревья, список проектов и данные корзины после мутаций.
- Полностью переиспользовать существующие owner-scoped endpoints и backend lifecycle без изменений API contract, DTO, repositories, services, use-cases или схемы.

## Impact

- Web: App Router, FSD-страница корзины, навигация, generated API exports и TanStack Query cache.
- API/Prisma: используются существующие owner-scoped endpoints и CQRS/use-case архитектура без изменений contracts, DTO, endpoints, Prisma schema и migrations. OpenAPI и generated API client из-за этого change не обновляются.
- Зависимости: новые пакеты не требуются.

Вне scope: массовая очистка корзин страниц и проектов, история версий, восстановление Yjs snapshot, assets/object storage, автопурж по расписанию, поиск, bulk selection, drag-and-drop и общий рефакторинг permissions.

Future Scope: массовая очистка корзин может рассматриваться отдельной задачей. Текущие endpoints выбирают динамический набор элементов на момент выполнения, поэтому такой UX потребовал бы отдельного решения о безопасном подтверждении охвата и возможных API изменениях; это не часть #87 MVP или текущего PR.

Зависимости: API корзины и lifecycle страниц/проектов уже реализованы. PR #93 влит; задача #47 по assets остаётся открытой и не блокирует этот MVP.
