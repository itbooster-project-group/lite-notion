## Why

Сейчас браузер ходит в три отдельных origin (`web:3000`, `api:3001`, `collaboration:3002`), а `apps/collaboration` держит собственное подключение к PostgreSQL, собственную копию `JWT_SECRET` и собственную сборку доменных пакетов. Из этого следуют три проблемы, которые нельзя решить по отдельности: у подписывающего секрета две копии; `PageDocument.yjsState` имеет двух слепых писателей без оптимистической блокировки; а открытое WebSocket-соединение не переавторизуется вообще — оно переживает и истечение access-токена, и отзыв прав.

Change вводит Envoy как единую точку входа, отвечающую за аутентификацию без авторизации, переводит collaboration на HTTP-доступ к API вместо прямого доступа к базе и снимает обе границы переавторизации, которые действующая спецификация требует снимать только вместе.

## What Changes

**API Gateway**

- Добавить Envoy как единственный публичный вход: `/` → web, `/api/v1/*` → API, `/collaboration` → collaboration runtime.
- Аутентифицировать REST-запросы фильтром `ext_authz`, который обращается к внутреннему эндпоинту API; проверка подписи остаётся единственной реализацией и живёт в API.
- Передавать личность вниз по стеку заголовками `X-User-Id` и `X-Session-Id`, **затирая** любые их клиентские копии на входе.
- Пропускать WebSocket upgrade на маршруте collaboration без аутентификации: токен приходит первым `Auth`-кадром внутри протокола и гейтвею структурно недоступен.
- Не публиковать наружу внутренние маршруты (`ext_authz`, проверка доступа, документный эндпоинт) и внутренние порты сервисов.

**Collaboration runtime**

- **BREAKING** Убрать из `apps/collaboration` прямой доступ к PostgreSQL: зависимости `@lite-notion/database` и `@lite-notion/page-permissions` уходят, `DATABASE_URL` и `DATABASE_CONNECTION_TIMEOUT_MS` уходят из конфигурации.
- **BREAKING** Убрать `JWT_SECRET` из конфигурации collaboration: сервис перестаёт верифицировать токены сам и получает личность вместе с вердиктом от API.
- Авторизовать подключение вызовом внутреннего эндпоинта API с **токеном самого клиента**, чтобы не появлялся привилегированный режим «действовать от имени пользователя».
- Загружать и сохранять `yjsState` через внутренний документный эндпоинт API под **сервисной** аутентификацией: у `onStoreDocument` пользователя в скоупе нет.
- Ввести переавторизацию в живом соединении через хук `onTokenSync`: по таймеру от `exp` сервер запрашивает у клиента свежий токен, повторяет проверку доступа, обновляет `connection.readOnly` при понижении роли и закрывает соединение при отказе. Снимает обе границы из требования «Изменение доступа и уже открытое соединение» одновременно.
- Различать отказ и недоступность: `401`/`403`/`404` от API закрывают соединение, недоступность и `5xx` — нет, соединение живёт в пределах ограниченного грейс-окна.
- Включить горизонтальное масштабирование через `@hocuspocus/extension-redis` (бамп `@hocuspocus/server` 4.6 → 4.7), чтобы реплики не расходились по in-memory `Y.Doc` и awareness.

**Удаления**

- **BREAKING** Удалить публичный `PUT /api/v1/pages/{pageId}/document` и `GET /api/v1/pages/{pageId}/document`: после миграции редактора у них нет потребителей, а `PUT` остаётся вторым слепым писателем, чей успешный `200` затирается ближайшим flush'ем Hocuspocus.
- **BREAKING** Удалить все три workspace-пакета и свернуть их в `apps/api`. После отказа collaboration от прямого доступа к данным у каждого из них остаётся ровно один потребитель — API, — и граница пакета перестаёт что-либо разделять:
  - `@lite-notion/auth-token` — рантайм теряет единственного потребителя, тип `AccessTokenPayload` возвращается в API;
  - `@lite-notion/database` — Prisma-схема, миграции и клиент переезжают в `apps/api`;
  - `@lite-notion/page-permissions` — модель прав переезжает в существующий модуль `apps/api/src/page-permissions`.
- Каталог `packages/` исчезает целиком; глоб `packages/*` уходит из `pnpm-workspace.yaml`, а хуки `prebuild`/`pretest`/`pretypecheck`/`preopenapi:generate` и корневой `dev:prepare` перестают собирать пакеты перед каждой командой.
- Удалить операции документа из OpenAPI snapshot и сгенерированного frontend-клиента вместе с их msw-хендлерами.

**Смежное**

- Зафиксировать в спеке действующий предел тела запроса: `JSON_BODY_LIMIT = '2mb'` уже покрывает `DOCUMENT_MAX_BYTES` в base64, но через HTTP теперь пойдут все flush'и документов, и инвариант перестаёт быть деталью реализации.
- Обновить `token()` в web-сессии: обновлять access-токен при приближении `exp`, иначе token-sync вернёт тот же протухающий токен.
- Добавить Redis и Envoy в docker compose и в LAN-runner.

## Capabilities

### New Capabilities

- `api-gateway`: единая точка входа, аутентификация REST-трафика без авторизации, изоляция внутренних маршрутов, маршрутизация HTTP и WebSocket upgrade.

### Modified Capabilities

- `collaboration-runtime`: доступ к данным только через HTTP к API; конфигурация без `JWT_SECRET` и `DATABASE_URL`; переавторизация живого соединения через token-sync; горизонтальное масштабирование через общий брокер.
- `page-documents`: удаление публичных REST-операций документа; внутренний служебный writer вместо публичного `PUT`; единственный источник изменений — collaboration runtime.
- `api-runtime-foundation`: внутренние маршруты и их изоляция от публичного периметра; личность запроса из заголовков гейтвея; лимит тела запроса; конфигурация окружения.
- `user-authentication`: правило защищённого маршрута переносится на гейтвей; внутренний эндпоинт проверки токена как единственная реализация верификации.
- `development-runtime`: docker compose с Redis и Envoy; единый origin вместо трёх; конфигурация collaboration без доступа к базе.
- `page-permissions`: владельцем единственной реализации модели становится API; сетевой вызов из другого сервиса перестаёт быть запрещённым и становится единственным предусмотренным способом узнать роль.
- `web-page-editor-collaboration`: обновление access-токена до истечения для поддержки серверного token-sync.

## Non-Goals

- Отзыв прав в реальном времени через событийный канал: enforcement остаётся в границах одного access-token TTL.
- Переход на асимметричную подпись: HS256 сохраняется, секрет остаётся ровно в API.
- Собственный gateway-сервис на Node: шлюз — это конфигурация прокси, а не ещё одно приложение с бизнес-логикой.

## Impact

- **Инфраструктура**: новый `apps/gateway` с конфигурацией Envoy; `docker-compose` получает `redis` и `envoy`; внутренние порты сервисов перестают публиковаться наружу; `scripts/dev-lan.mjs` переводится на один origin.
- **Backend**: новые внутренние модули API (проверка токена для `ext_authz`, проверка доступа к странице, документный эндпоинт под сервисной аутентификацией); удаление `PageDocumentController`; замена `JwtStrategy` на чтение заголовков гейтвея.
- **Collaboration**: `page-access.ts` и `persistence.ts` переходят с Prisma на HTTP-клиент; `config/environment.ts` теряет три переменные и получает адрес API и сервисный креденшл; `collaboration-server.ts` получает `onTokenSync`, таймеры дедлайна и Redis-расширение.
- **Frontend**: `token()` в `features/page-editing`; `NEXT_PUBLIC_API_BASE_URL` и `NEXT_PUBLIC_COLLABORATION_URL` схлопываются в один origin; чистка сгенерированного клиента.
- **Пакеты**: удаляются все три — `@lite-notion/auth-token`, `@lite-notion/database`, `@lite-notion/page-permissions`. Prisma-схема и миграции переезжают в `apps/api/prisma`, клиент и константы — в `apps/api/src/database`, модель прав — в `apps/api/src/page-permissions`. Около 25 мест импорта переписываются на относительные пути; `paths` в `tsconfig.base.json` нет, поэтому переезд не требует правки резолюции модулей.
- **Зависимости**: `+@hocuspocus/extension-redis`, бамп `@hocuspocus/server` и `@hocuspocus/provider` до 4.7; `−jsonwebtoken` в collaboration.
- **Безопасность**: сетевая изоляция API и collaboration становится несущим контролем, а не удобством — при прямом доступе к API заголовки личности подделываются тривиально.

## Out of Scope

- Отзыв прав в реальном времени через брокер: enforcement остаётся в границах одного access-token TTL, событийный канал отзыва не вводится.
- Переход на асимметричную подпись (RS256/JWKS): подпись остаётся HS256, секрет остаётся ровно в API.
- TLS-терминация и production-конфигурация Envoy сверх той, что нужна для локального и LAN-окружения.
- Проверка состояния сессии в базе на каждом запросе: `JwtStrategy` и сейчас её не делает, и это остаётся принятым компромиссом.
- Замена BullMQ, Socket.IO и любые другие применения Redis вне синхронизации реплик collaboration.
