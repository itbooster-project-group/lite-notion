## Context

См. `proposal.md` — Why. Корневой список и форма создания находятся в `pages/workspace`; `Dialog` и общие controls экспортируются из `shared/ui`. `Modal` обслуживает мобильный drawer и не подходит для формы. Desktop и mobile сайдбары собраны в `widgets/app-shell`; их состояние уже управляется существующим store.

## Goals / Non-Goals

**Goals:**

- Ограничить изменения композицией корневой страницы и верхнего заголовка app shell.
- Использовать существующие controls, диалог и utility-классы с текущими темами и акцентом.
- Сохранить все текущие операции проектов, навигацию и состояние сайдбара.

**Non-Goals:**

- Менять API, бизнес-логику, дизайн-токены, глобальные стили или мобильное поведение app shell.

## Decisions

- Держать состояние открытия диалога и ошибки формы локально в корневой композиции. Использовать существующий `Dialog`, `DialogContent`, `DialogClose` и текущий form submit handler с `Input`; передавать фокус полю при открытии. Escape и «Отмена» закрывают диалог в обычном состоянии, а повторное открытие очищает старую ошибку. Пока запрос ожидает ответа, блокировать повторный submit. Не вводить новый feature/UI-компонент.
- Оставить ссылку перехода и кнопку меню соседними интерактивными элементами карточки. Добавить `Folder` из уже используемого `lucide-react`; использовать тонкую рамку без постоянной выраженной тени, умеренные hover/focus-состояния и локальную типографику. Длинное название должно переноситься или обрезаться безопасно, не расширяя карточку. Сетка должна ограничивать ширину карточек и адаптироваться к viewport.
- Использовать существующий текстовый идентификатор приложения `Lite Notion` слева в desktop sidebar header и текущий toggle справа. В collapsed режиме скрывать текст, сохраняя кнопку раскрытия с текущим доступным именем и tooltip через общий `Button`. На mobile оставить drawer, его верхнюю кнопку закрытия и внешний trigger без изменений; не добавлять второй переключатель.
- Согласовать базовую высоту desktop-заголовка сайдбара и рабочей области в 64 px: увеличить sidebar row с `h-12` до `h-16`, дать шапке рабочей области `min-h-16` и добавить нижнюю линию под sidebar row. Содержимое обеих строк центрировать по вертикали. Сохранить перенос длинных хлебных крошек: основная шапка может расти выше базовой строки без обрезания текста.
- Сохранить `ContentContainer`, типографику и палитру; локально настроить отступы и сетку Tailwind без theme tokens. Изменение не требует миграции; откат состоит в возврате UI к прежней компоновке.
- Обновить существующие интеграционные тесты корневой рабочей области и app shell по пользовательскому поведению: пустой список, submit/ошибка/повторное открытие, навигация карточки и независимость меню действий, а также sidebar toggle и mobile close. Не проверять декоративные CSS-классы.

## Risks / Trade-offs

- Автопереход после успешного создания закрывает диалог через переход с текущей страницы; это сохраняет существующий контракт создания и не требует дополнительной логики закрытия.
- В проекте нет отдельного переиспользуемого компонента иконки папки; используется иконка из уже установленного набора Lucide без создания новой абстракции.
- Автоматическое фокусирование управляется диалоговым primitive и атрибутом поля; проверка должна подтвердить фактический фокус в тестовом окружении.
