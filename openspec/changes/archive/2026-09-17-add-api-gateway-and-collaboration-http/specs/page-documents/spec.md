## ADDED Requirements

### Requirement: Внутренний документный эндпоинт обслуживает collaboration runtime

API MUST публиковать внутренние операции чтения и записи содержимого документа, предназначенные исключительно для collaboration runtime. Эти операции MUST быть недоступны через публичный периметр и MUST NOT попадать в публикуемый OpenAPI-документ.

Внутренние операции MUST аутентифицироваться сервисным креденшлом, а не access-токеном пользователя: у сохранения документа нет пользователя в скоупе — оно выполняется после отложенного flush и может произойти после ухода последнего клиента комнаты. Обращение без действующего сервисного креденшла MUST отклоняться.

Внутренние операции MUST NOT проверять роль пользователя: право на содержимое установлено при допуске в комнату и подтверждается переавторизацией соединения, а предъявить пользователя на отложенном сохранении нечем. Доступ к ним ограничивает сервисный креденшл. Они MUST проверять только инварианты хранения: страница существует, документ существует, `Page.deletedAt` пуст.

Запись MUST выполняться одним transactional/conditional write, атомарно проверяющим инвариант живости и записывающим `yjsState`, `storageRevision` и timestamp. Нулевое число затронутых строк MUST сообщаться вызывающему отличимым от прочих ошибок способом, чтобы collaboration runtime мог завершить комнату, а не повторять попытку.

Принимаемый размер содержимого MUST покрывать `DOCUMENT_MAX_BYTES` в той кодировке, в которой содержимое передаётся. Предел тела запроса MUST NOT быть ниже этой величины.

#### Scenario: Collaboration читает содержимое документа
- **WHEN** collaboration runtime запрашивает содержимое документа живой страницы с действующим сервисным креденшлом
- **THEN** API возвращает сохранённый Yjs state

#### Scenario: Collaboration записывает содержимое документа
- **WHEN** collaboration runtime записывает Yjs state живой страницы с действующим сервисным креденшлом
- **THEN** API сохраняет состояние, инкрементирует `storageRevision` атомарно с записью и обновляет timestamp

#### Scenario: Обращение без сервисного креденшла отклоняется
- **WHEN** обращение к внутренней документной операции не содержит действующий сервисный креденшл
- **THEN** API отклоняет его и не изменяет содержимое

#### Scenario: Запись в удалённую страницу отличима от прочих ошибок
- **WHEN** collaboration runtime записывает содержимое документа страницы, помеченной удалённой
- **THEN** conditional write затрагивает `0` строк
- **AND** ответ API позволяет вызывающему отличить этот случай от временной ошибки

#### Scenario: Документ предельного размера принимается
- **WHEN** collaboration runtime записывает содержимое, равное `DOCUMENT_MAX_BYTES`
- **THEN** запрос не отклоняется из-за предела размера тела

#### Scenario: Внутренние операции недоступны снаружи
- **WHEN** внешний клиент обращается к внутренней документной операции через публичный периметр
- **THEN** обращение отклоняется до попадания в API

### Requirement: У содержимого документа ровно один writer

Единственным источником изменений `PageDocument.yjsState` MUST быть collaboration runtime. Публичный HTTP-интерфейс MUST NOT предоставлять операции записи содержимого документа ни одному клиенту.

Frontend MUST получать и изменять содержимое документа исключительно через collaboration-транспорт. Он MUST NOT читать содержимое по HTTP, MUST NOT выполнять HTTP-автосохранение и MUST NOT использовать HTTP-запись как резервный путь при недоступности WebSocket.

Метаданные страницы — заголовок, родитель, ранг, режим наследования, разрешения — MUST продолжать изменяться через публичный HTTP-интерфейс: их этот запрет не касается.

#### Scenario: Публичной записи содержимого не существует
- **WHEN** клиент обращается к публичному HTTP-интерфейсу за операцией записи содержимого документа
- **THEN** такой операции не существует

#### Scenario: Редактор сохраняет изменения только через collaboration
- **WHEN** пользователь изменяет содержимое страницы в редакторе
- **THEN** изменение уходит collaboration runtime
- **AND** frontend не отправляет HTTP-запрос с содержимым документа

#### Scenario: Обрыв WebSocket не включает резервный HTTP-путь
- **GIVEN** collaboration-соединение находится в состоянии переподключения или офлайн
- **WHEN** пользователь продолжает изменять содержимое
- **THEN** frontend не отправляет содержимое по HTTP
- **AND** изменение остаётся в жизненном цикле локальной сессии до восстановления соединения

#### Scenario: Метаданные страницы по-прежнему меняются по HTTP
- **WHEN** пользователь переименовывает страницу или меняет её режим наследования
- **THEN** операция выполняется публичным HTTP-интерфейсом

### Requirement: Изоляция доступа к содержимому документа

Ни одна операция, связанная с содержимым документа, MUST NOT раскрывать существование страницы, к которой у текущего пользователя нет доступа. Отсутствие доступа и отсутствие страницы MUST приводить к неразличимому снаружи результату.

Доступ к документу MUST определяться той же моделью, что и доступ к его странице: отдельных разрешений у документа MUST NOT быть.

Поскольку публичных операций над содержимым не существует, изоляция MUST обеспечиваться на допуске в комнату и при переавторизации соединения. Различение «доступ есть, но роли не хватает для записи» MUST выражаться режимом соединения — read-only, — а не отказом: скрывать существование документа, который пользователь и так читает, не от кого.

#### Scenario: Недоступная и несуществующая страница неразличимы
- **WHEN** пользователь подключается к комнате страницы, на которую ему ничего не выдано, и затем к комнате несуществующей страницы
- **THEN** оба подключения отклоняются одинаково

#### Scenario: Читатель получает соединение без права записи
- **GIVEN** пользователю выдан `viewer` на чужой странице
- **WHEN** он подключается к её комнате
- **THEN** соединение открывается в режиме read-only
- **AND** отказа в подключении не происходит

#### Scenario: Причина отказа не раскрывается
- **WHEN** аутентифицированный пользователь подключается к комнате страницы, на которую ему ничего не выдано
- **THEN** отказ не сообщает, существует ли страница

## REMOVED Requirements

### Requirement: Чтение содержимого документа
**Reason**: После миграции редактора на collaboration-транспорт у публичного `GET /api/v1/pages/{pageId}/document` не осталось потребителей. Содержимое доставляется первичной Yjs-синхронизацией комнаты, а сохранение публичной операции чтения оставляло бы бинарное состояние документа доступным вторым путём с собственной моделью ошибок.

**Migration**: Читать содержимое через подключение к комнате `page:<pageId>` collaboration runtime. Метаданные страницы продолжают читаться публичным HTTP-интерфейсом. Внутренняя операция чтения доступна только collaboration runtime по сервисному креденшлу.

### Requirement: Замена содержимого документа
**Reason**: Публичный `PUT /api/v1/pages/{pageId}/document` — второй слепой writer того же `yjsState`. Проверки `storageRevision` при записи нет, поэтому успешный `200` затирается ближайшим отложенным сохранением активной комнаты: клиент получает подтверждение записи, которой через секунду не существует.

**Migration**: Записывать содержимое через collaboration-транспорт. Сохранение в базу выполняет collaboration runtime через внутреннюю документную операцию под сервисным креденшлом.

### Requirement: Документирование операций документа в OpenAPI
**Reason**: Публичных операций над содержимым документа больше нет, а внутренние операции не входят в публикуемый контракт.

**Migration**: Удалить операции документа из OpenAPI snapshot, сгенерированного frontend-клиента и mock-сценариев.

### Requirement: Document write ownership transitions to collaboration without dual writers
**Reason**: Требование описывало переходный период, в котором REST-запись сохранялась как временный путь совместимости до отдельного change по её удалению. Этот change и есть то удаление: переходное состояние закончилось.

**Migration**: Заменено требованием «У содержимого документа ровно один writer».

### Requirement: Frontend document writes use collaboration while REST PUT remains compatible
**Reason**: Требование фиксировало сосуществование мигрировавшего frontend и совместимого REST `PUT`. После удаления публичной записи сосуществовать нечему.

**Migration**: Заменено требованием «У содержимого документа ровно один writer», которое сохраняет запреты на HTTP-чтение содержимого, HTTP-автосохранение и HTTP-fallback при обрыве WebSocket.

### Requirement: Изоляция документов по доступу
**Reason**: Требование описывало изоляцию через коды ответов публичных REST-операций над документом — одинаковый `404` для недоступной и несуществующей страницы и `403` ровно в случае нехватки роли для записи. Публичных операций над содержимым больше нет, поэтому формулировки через HTTP-статусы этих операций описывать нечего.

**Migration**: Заменено требованием «Изоляция доступа к содержимому документа», которое сохраняет обе гарантии — неразличимость отсутствия доступа и отсутствия страницы, и отсутствие отказа для читателя — но выражает их через допуск в комнату и режим соединения.
