## Context

Оба дерева (`WorkspaceTree`, `PageTree`) используют `dragAndDropFeature` и `keyboardDragAndDropFeature` из `@headless-tree/core@1.7.0`. `canDrop`/`onDrop` переводят `DragTarget` библиотеки в `PageDropTarget` через адаптеры `toWorkspaceDropTarget`/`toPageDropTarget`, затем в `MoveIntent` через `toMoveIntent` и проверяют `isMoveIntentValid`. Мотивация и три причины бага — в proposal.md, раздел Why.

Существенная для решения деталь поведения библиотеки (по исходникам `getDragTarget`/`getTargetPlacement`): перед тем как предложить вставку рядом с наведённой строкой, библиотека вызывает `canDrop` с **неупорядоченной** целью `{ item: parent }` («может ли страница вообще стать ребёнком этого родителя»). Та же неупорядоченная форма используется для drop «сделать дочерним» на строку `parent`. Поэтому ответ `canDrop` на `{ item: parent }` одновременно разрешает или запрещает и перестановку среди детей `parent`, и drop на саму строку `parent`.

## Goals / Non-Goals

**Goals:**
- Перестановка страницы на одном уровне мышью (верх/низ строки) в обоих деревьях, включая корневой уровень проекта.
- Одна линия вставки на дерево, одинаковая в обоих представлениях.
- Сохранить единую проверку допустимости `isMoveIntentValid` для всех путей (мышь, клавиатура, диалог).

**Non-Goals:**
- Расширение жеста reparent сверх встроенной эвристики библиотеки.
- Touch-специфичная эргономика, multi-select drag, перенос между проектами.
- Изменения `MovePageDialog` и серверного API перемещения.
- Индикатор вставки при перетаскивании блоков редактора — отдельный change.

## Decisions

**1. Включить `canReorder: true` в обоих деревьях.**
Без него `getTargetPlacement` сразу возвращает «сделать дочерним», и ни позиции «перед/после», ни `dragLineIndex`/`dragLineLevel` не вычисляются. Зона перестановки — стандартные 30% сверху/снизу строки (`reorderAreaPercentage` по умолчанию); отдельная настройка не нужна, пока пользователи не сообщат о неудобстве.

**2. `PageDropTarget` типа `item` несёт `childPageIds`, индекс считает `toMoveIntent`.**
Индекс «в конец родителя» должен считаться среди siblings без перемещаемой страницы — ровно как `getMoveTargetSiblings` внутри `isMoveIntentValid`. Адаптер не знает перетаскиваемую страницу, а `toMoveIntent` знает, поэтому цель передаёт список id детей, а `toMoveIntent` фильтрует `pageId`. Исправление в одном месте `entities/page` покрывает оба дерева.
- *Альтернатива*: передавать id перетаскиваемой страницы в каждый адаптер. Отклонена: дублирует правило в двух деревьях и оставляет `childCount` с неоднозначной семантикой.

**3. Неупорядоченная цель-проект — корень проекта.**
В `toWorkspaceDropTarget` неупорядоченная цель `{ item: project }` превращается в `item`-цель с `parentPageId: null`. Иначе проверка `{ item: parent }` для корневых страниц всегда ложна и перестановка на корневом уровне невозможна. Побочный эффект — drop на строку своего проекта делает страницу последней корневой; перенос в чужой проект по-прежнему отсекает `isMoveIntentValid` (проверка `projectId`). Разделить эти два случая в `canDrop` нельзя (см. Context), поэтому спецификация «проекты не являются целями DnD» заменяется этим поведением.
- *Альтернатива*: отличать случаи через `draggingOverItem`. Отклонена: на момент вызова `canDrop` это поле ещё хранит предыдущий элемент — хрупкая зависимость от порядка обновлений внутри библиотеки.

**4. Общий `TreeDropIndicator` в `shared/ui`.**
Компонент принимает готовый `CSSProperties` из `tree.getDragLineStyle()` (библиотека сама возвращает `{ display: 'none' }` вне активного перетаскивания) и рендерится внутри контейнера дерева с `position: relative`. Расположение в `shared/ui` — потому что его используют и widget (`workspace-navigation`), и feature (`workspace-management`), а FSD запрещает кросс-импорт между ними.

## Risks / Trade-offs

- **[Risk]** `getDragLineStyle`/`getDragLineData` — низкоуровневые API `@headless-tree/core`, поведение может измениться при обновлении. → Версия уже зафиксирована (`^1.7.0`); unit-тест компонента индикатора и регрессионные тесты `toMoveIntent`.
- **[Risk]** Зона перестановки (~10px при высоте строки 36px) узкая. → Принято как поведение библиотеки по умолчанию; при жалобах можно увеличить `reorderAreaPercentage` без изменения архитектуры.
- **[Trade-off]** Drop на строку проекта теперь перемещает страницу в корень проекта — изменение спецификации, согласованное с пользователем.
- **[Trade-off]** Жест reparent остаётся узким (только на свёрнутом последнем элементе группы). Для произвольного уровня — диалог «Переместить…» или drop на строку проекта.
