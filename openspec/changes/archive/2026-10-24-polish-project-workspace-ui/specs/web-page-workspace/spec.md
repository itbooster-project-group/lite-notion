## MODIFIED Requirements

### Requirement: Единая приватная рабочая область

Web-приложение ДОЛЖНО (MUST) показывать единую рабочую область на `/`, `/projects/{projectId}` и `/pages/{pageId}`. `/` ДОЛЖЕН показывать список всех проектов и действие создания проекта, открывающее компактный диалог с полем названия; поле ДОЛЖНО получать фокус при открытии, а форма ДОЛЖНА поддерживать подтверждение клавишей Enter. Диалог ДОЛЖЕН закрываться клавишами Escape и действием отмены; повторное открытие после ошибки ДОЛЖНО очищать устаревшее сообщение. Пустое или превышающее 255 символов название ДОЛЖНО отклоняться текущей валидацией. Во время запроса повторная отправка ДОЛЖНА блокироваться; состояния ожидания и ошибка запроса ДОЛЖНЫ быть доступны пользователю. После успешного создания система ДОЛЖНА обновить список и перейти к созданному проекту.

Карточки проектов ДОЛЖНЫ показывать иконку папки из уже используемого набора и чёткий заголовок, иметь тонкую рамку без выраженной постоянной тени и ненавязчивые hover/focus-состояния. Длинные названия ДОЛЖНЫ переноситься либо безопасно обрезаться, не заставляя карточку расширяться за пределы сетки. Адаптивная сетка ДОЛЖНА сохранять разумные минимальную и максимальную ширину карточек. Переход по существующей ссылке проекта и меню действий ДОЛЖНЫ оставаться раздельными доступными действиями.

`/projects/{projectId}` ДОЛЖЕН выбирать проект без активной страницы; `/pages/{pageId}` ДОЛЖЕН выбирать страницу независимо от глубины. Недоступные идентификаторы ДОЛЖНЫ показывать единое безопасное состояние со ссылкой на `/`.

#### Scenario: Список проектов

- **КОГДА** пользователь открывает `/`
- **ТОГДА** рабочая область показывает список проектов и действие «Создать проект»

#### Scenario: Открытие создания проекта

- **КОГДА** пользователь активирует действие «Создать проект»
- **ТОГДА** открывается диалог с сфокусированным полем названия проекта

#### Scenario: Создание проекта с клавиатуры

- **КОГДА** пользователь вводит допустимое название и нажимает Enter
- **ТОГДА** проект создаётся, появляется в кэше списка, и пользователь переходит к нему

#### Scenario: Ошибка проверки или создания проекта

- **КОГДА** название пустое, превышает допустимую длину или запрос создания завершается ошибкой
- **ТОГДА** диалог показывает понятную ошибку и позволяет исправить название или повторить запрос

#### Scenario: Закрытие и повторное открытие диалога

- **КОГДА** пользователь закрывает диалог клавишей Escape или действием «Отмена» и открывает его снова после ошибки
- **ТОГДА** диалог закрывается, а устаревшее сообщение об ошибке не отображается при повторном открытии

#### Scenario: Повторная отправка во время запроса

- **КОГДА** запрос создания проекта ещё выполняется и пользователь повторно отправляет форму
- **ТОГДА** второй запрос не отправляется, а интерфейс показывает текущее состояние ожидания

#### Scenario: Пустой список проектов

- **КОГДА** API возвращает пустой список проектов
- **ТОГДА** рабочая область предлагает создать первый проект и не показывает пустую форму постоянно

#### Scenario: Карточки проектов сохраняют навигацию и меню действий

- **КОГДА** пользователь выбирает ссылку проекта или его меню действий с клавиатуры
- **ТОГДА** ссылка открывает проект, а меню открывает свои действия без запуска перехода

#### Scenario: Длинное название проекта

- **КОГДА** карточка отображает длинное название проекта
- **ТОГДА** название переносится или обрезается в пределах карточки, не растягивая сетку

#### Scenario: Открытие проекта

- **КОГДА** пользователь открывает доступный `/projects/{projectId}`
- **ТОГДА** рабочая область показывает в контентной области дерево страниц этого проекта без активной страницы
