## Why

В API нет ни пользователей, ни аутентификации: `apps/api` публикует только `GET /api/v1/health`, а Prisma schema не содержит ни одной модели. Любая продуктовая функциональность Lite Notion — заметки, документы, проекты — принадлежит конкретному владельцу, поэтому без учётных записей и защищённых маршрутов дальнейшая разработка backend невозможна. Аутентификация становится блокирующей предпосылкой для всех следующих изменений.

## What Changes

- Появляются Prisma-модели `User` и `Session` и первая продуктовая миграция. Пароль хранится только как bcrypt-хеш; refresh-токен хранится только как SHA-256 хеш.
- Регистрация по email, nickname и паролю без подтверждения email. Email уникален и нормализуется до нижнего регистра.
- Вход по email и паролю выдаёт короткоживущий access JWT в теле ответа и долгоживущий opaque refresh-токен в `httpOnly` cookie. Сессия материализуется строкой в таблице `Session`.
- Обновление пары токенов с ротацией refresh-токена, обнаружением повторного использования (reuse detection) и отзывом всей цепочки сессий при обнаружении утечки.
- **Grace-период 30 секунд**: только что ротированный refresh-токен остаётся принимаемым 30 секунд, чтобы параллельные запросы клиента и потерянные ответы не разлогинивали пользователя. Предъявление отозванного токена после истечения grace-периода трактуется как утечка.
- Выход инвалидирует текущую сессию в базе и очищает cookie; поддерживается выход со всех устройств.
- Эндпоинт текущего пользователя `GET /api/v1/auth/me`.
- Глобальный guard закрывает все маршруты по умолчанию; публичные маршруты помечаются явным декоратором `@Public()`. Существующий `GET /api/v1/health` помечается публичным и сохраняет текущий контракт.
- Неверные учётные данные всегда отвечают одинаково и не позволяют отличить несуществующий email от неверного пароля.
- Плановая задача по расписанию удаляет истёкшие и давно отозванные сессии.
- **BREAKING** (контракт окружения): добавляются обязательные переменные `JWT_SECRET`, `ACCESS_TOKEN_TTL_S`, `REFRESH_TOKEN_TTL_S`, `BCRYPT_ROUNDS`. Существующие развёртывания и локальные `.env` без них не запустятся.
- **BREAKING** (контракт CORS): cross-origin credentials разрешаются для единственного разрешённого origin — иначе браузер не отправит refresh cookie. Wildcard origin по-прежнему запрещён.

Явно вне scope:

- Восстановление пароля, смена пароля, подтверждение email.
- Вход через внешних провайдеров и OAuth.
- Ролевая авторизация сверх разделения «авторизован / не авторизован»: в MVP все действия выполняет владелец над своими данными.
- Rate limiting и защита от brute force при входе.
- Управление списком активных сессий из UI.
- Frontend-реализация: формы, страницы, хранение access-токена, silent refresh. Изменение затрагивает web только регенерацией сгенерированного из OpenAPI кода.

## Capabilities

### New Capabilities

- `user-authentication`: учётные записи с email и паролем, серверные сессии в PostgreSQL, выдача и ротация токенов с grace-периодом, защита маршрутов по умолчанию, единообразные ответы на неверные учётные данные и плановая очистка устаревших сессий.

### Modified Capabilities

- `api-runtime-foundation`: требование «Валидируемая конфигурация окружения» расширяется четырьмя обязательными переменными аутентификации; требование «Ограниченный CORS-доступ» меняется — cross-origin credentials теперь разрешены для точного совпадения с `CORS_ORIGIN`; требование «Непроизводственная OpenAPI-документация» перестаёт описывать документ как содержащий единственный health path.

## Impact

Затронутый код (`apps/api`):

- `prisma/schema.prisma` и новая директория `prisma/migrations` — модели `User`, `Session`, первая миграция.
- `src/config/environment.ts`, `src/config/application-config.ts` и их спеки — четыре новые валидируемые переменные.
- `src/application.ts` — `credentials: true` в CORS, `cookie-parser`, Swagger security scheme для bearer-токена.
- `src/app.module.ts` — регистрация `AuthModule`, `ScheduleModule` и глобального `APP_GUARD`.
- `src/health/health.controller.ts` — пометка `@Public()`.
- Новый модуль `src/auth/**` — контроллер, сервисы, guard, стратегия, DTO, декораторы, задача очистки сессий и их тесты.
- Новый модуль `src/users/**` — доступ к `User` через Prisma.
- `apps/api/.env.example` — новые переменные с рекомендованными локальными значениями.
- `apps/api/openapi.json` — регенерируется командой `pnpm api:generate`.

Затронутый код (`apps/web`):

- Сгенерированный из OpenAPI клиент, типы и MSW handlers — регенерируются той же командой и коммитятся. Ручной frontend-код не меняется.

Зависимости (`apps/api`): добавляются `@nestjs/jwt`, `@nestjs/passport`, `passport`, `passport-jwt`, `bcrypt`, `cookie-parser`, `@nestjs/schedule` и соответствующие `@types/*`. Ни одна из них не используется другим workspace-пакетом, поэтому catalog не затрагивается.

Инфраструктура: не затронута. Redis, BullMQ и Socket.IO остаются отсутствующими — плановая очистка сессий выполняется в процессе API через `@nestjs/schedule`, без брокера.
