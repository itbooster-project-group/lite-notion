## ADDED Requirements

### Requirement: Представление страницы несёт режим и роль
Каждое представление страницы, которое возвращает API, MUST содержать её режим наследования доступа и эффективную роль текущего пользователя на ней. Это относится и к одной странице, и к каждому узлу дерева, и к каждому узлу выдачи доступных страниц.

Роль MUST быть одной из `owner`, `editor` и `viewer`. Отсутствие доступа значением роли MUST NOT быть: страницу, к которой доступа нет, API не возвращает вовсе.

Без этих полей клиент не может решить, открывать ли редактор доступным для записи, и вынужден узнавать роль по факту отказа. Ни то, ни другое поле MUST NOT приниматься от клиента ни одной операцией над страницами.

#### Scenario: Роль в дереве владельца
- **WHEN** пользователь запрашивает `GET /api/v1/pages`
- **THEN** у каждого узла эффективная роль равна `owner`, а режим наследования соответствует хранимому

#### Scenario: Роль при чтении доступной чужой страницы
- **GIVEN** пользователю выдан `viewer` на чужой странице
- **WHEN** он запрашивает эту страницу
- **THEN** API отвечает `200`, и роль в ответе равна `viewer`

#### Scenario: Роль и режим не принимаются от клиента
- **WHEN** запрос создания или переименования страницы содержит роль либо режим наследования
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не изменяет страницу

### Requirement: Изоляция дерева по доступу
Ни одна операция над страницами MUST NOT раскрывать существование страницы или проекта, к которым у текущего пользователя нет доступа. Для недоступной и для несуществующей записи API MUST отвечать одинаковым HTTP status `404` и одинаковым телом ответа — это относится и к самой адресуемой странице, и к идентификаторам проекта, родителя и соседей внутри тела запроса.

Удалённая страница и удалённый проект MUST быть неотличимы от несуществующих во всех операциях, кроме чтения корзины и восстановления: создание, чтение, переименование и перемещение MUST отвечать на них тем же `404` и тем же телом, что и на несуществующие. Удалённая страница MUST NOT быть ни родителем создаваемой страницы, ни целью и ни соседом перемещения.

Ответ `403` MUST использоваться в единственном случае: текущий пользователь вправе видеть адресуемую страницу, но его роли не хватает для запрошенной операции. Скрывать существование страницы, которую он и так читает, не от кого, а `404` на ней означал бы для клиента, что страница исчезла. Во всех остальных случаях `403` MUST NOT использоваться: он отличал бы существующую недоступную страницу от несуществующей.

Ни одна операция MUST NOT изменять владельца существующей страницы. Передача владения MUST NOT быть доступна ни через маршруты страниц, ни через маршруты разрешений.

Проект страницы MUST NOT изменяться ничем, кроме восстановления страницы из удалённого проекта, и только в живой проект того же владельца. Создание, чтение, переименование, перемещение и удаление MUST оставлять проект неизменным; отдельной операции переноса между проектами MUST NOT быть.

#### Scenario: Недоступная и несуществующая страница неразличимы
- **WHEN** пользователь адресует страницу, на которую ему ничего не выдано, и затем идентификатор, которому не соответствует ни одна страница, одной и той же операцией
- **THEN** оба ответа имеют одинаковый статус `404` и одинаковое тело

#### Scenario: Удалённая и несуществующая страница неразличимы
- **WHEN** пользователь адресует свою удалённую страницу и затем идентификатор, которому не соответствует ни одна страница, операцией чтения, переименования или перемещения
- **THEN** оба ответа имеют одинаковый статус `404` и одинаковое тело

#### Scenario: Удалённая страница не принимается родителем или соседом
- **WHEN** пользователь указывает удалённую страницу родителем создаваемой страницы либо родителем или соседом при перемещении
- **THEN** API отвечает `404` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Недостаточная роль на видимой странице отвечает запретом
- **GIVEN** пользователю выдан `viewer` на чужой странице
- **WHEN** он пытается её переименовать
- **THEN** API отвечает `403` в едином формате HTTP-ошибок и не изменяет страницу
- **AND** чтение той же страницы этим же пользователем по-прежнему отвечает `200`

#### Scenario: Отсутствие доступа не отвечает запретом
- **WHEN** аутентифицированный пользователь выполняет любую операцию над страницей, на которую ему ничего не выдано
- **THEN** API не отвечает статусом `403`

#### Scenario: Владелец не меняется существующими операциями
- **WHEN** пользователь выполняет создание, переименование, перемещение или удаление
- **THEN** идентификаторы владельца и проекта затронутых страниц остаются неизменными
- **AND** владелец не изменяется ни восстановлением, ни выдачей разрешения

## MODIFIED Requirements

### Requirement: Страница как узел дерева владельца
Страница MUST принадлежать ровно одному пользователю-владельцу, ровно одному проекту и MUST иметь необязательную ссылку на родительскую страницу. Страница без родителя — root-страница дерева.

Родитель и ребёнок MUST совпадать и по владельцу, и по проекту. Оба ограничения MUST быть закреплены на уровне базы данных, а не только проверкой в приложении: сохранение страницы, у которой родитель принадлежит другому пользователю либо лежит в другом проекте, MUST быть невозможно. Как следствие, дерево MUST NOT растягиваться на два проекта.

Каждая страница MUST иметь заголовок, строковый ранг порядка среди братьев и создателя. Создатель MUST фиксировать фактического автора операции и MUST NOT быть обязан совпадать с владельцем: страницу в дереве владельца создаёт и тот, кому выдано право её изменять. Создание страницы MUST в той же транзакции создавать ровно одну связанную запись документа страницы; страница без документа и документ без страницы MUST быть невозможны. Создаваемая запись документа MUST инициализироваться пустым содержимым.

Каждая страница MUST иметь режим наследования доступа. Режим управляет только тем, где останавливается наследование разрешений; ни на владельца, ни на состав дерева, ни на порядок братьев он MUST NOT влиять.

Страница MUST иметь отметку удаления. Все операции чтения MUST исключать страницы с проставленной отметкой удаления. Единственное исключение — чтение корзины, которое возвращает только их.

Удаление MUST быть согласованным по дереву: страница без отметки удаления MUST NOT иметь ни родительской страницы с отметкой удаления, ни проекта с отметкой удаления. Живая страница внутри удалённого поддерева и живая страница в удалённом проекте MUST быть невозможны.

#### Scenario: Владелец root-страницы
- **GIVEN** аутентифицированный пользователь со своим проектом
- **WHEN** он создаёт страницу без родителя
- **THEN** созданная страница принадлежит ему, лежит в указанном проекте, не имеет родителя и получает связанную запись документа с пустым содержимым
- **AND** создателем страницы записан он сам

#### Scenario: Владелец и проект наследуются от родителя
- **WHEN** пользователь создаёт страницу с родителем из доступного ему дерева
- **THEN** созданная страница принадлежит тому же владельцу и лежит в том же проекте, что и родитель

#### Scenario: Создатель отличается от владельца
- **GIVEN** пользователю выдан `editor` на чужой странице
- **WHEN** он создаёт под ней дочернюю страницу
- **THEN** владельцем созданной страницы записан владелец родителя, а создателем — он сам

#### Scenario: Разные владельцы у родителя и ребёнка отвергаются базой
- **WHEN** предпринимается попытка сохранить страницу, чей идентификатор владельца не совпадает с идентификатором владельца её родителя, в обход прикладных проверок
- **THEN** база данных отклоняет запись нарушением constraint, и страница не появляется

#### Scenario: Разные проекты у родителя и ребёнка отвергаются базой
- **WHEN** предпринимается попытка сохранить страницу, чей идентификатор проекта не совпадает с идентификатором проекта её родителя, в обход прикладных проверок
- **THEN** база данных отклоняет запись нарушением constraint, и страница не появляется

#### Scenario: Удалённая страница не видна в чтениях
- **WHEN** у страницы проставлена отметка удаления
- **THEN** ни выдача дерева, ни чтение одной страницы её не возвращают

#### Scenario: Живой потомок удалённой страницы невозможен
- **WHEN** страница помечена удалённой
- **THEN** ни один её потомок на любой глубине не остаётся без отметки удаления

#### Scenario: Живая страница в удалённом проекте невозможна
- **WHEN** проект помечен удалённым
- **THEN** ни одна его страница не остаётся без отметки удаления

### Requirement: Создание страницы
API MUST публиковать защищённый `POST /api/v1/pages`, принимающий обязательный идентификатор проекта, необязательный идентификатор родителя и необязательный заголовок. Создателем создаваемой страницы MUST становиться текущий пользователь; идентификатор владельца и идентификатор создателя MUST NOT приниматься от клиента.

При отсутствии идентификатора родителя MUST создаваться root-страница. Создавать root-страницу MUST быть вправе только владелец проекта: проект MUST принадлежать текущему пользователю, и владельцем создаваемой страницы MUST становиться он сам.

При указанном родителе MUST создаваться дочерняя страница. Родитель MUST требовать от текущего пользователя роли `editor` или выше; роли `viewer` MUST NOT хватать. Владелец и проект создаваемой страницы MUST наследоваться от родителя, а идентификатор проекта в запросе MUST совпадать с проектом родителя.

Новая страница MUST помещаться последней среди своих братьев. Клиент MUST NOT иметь возможности задать ранг порядка напрямую. Создаваемая страница MUST получать режим наследования `inherit` и MUST NOT получать собственных прямых разрешений: доступ к ней наследуется от родителя.

Успешное создание MUST отвечать `201` и возвращать созданную страницу с её идентификатором, владельцем, проектом, родителем, заголовком, рангом, режимом наследования, эффективной ролью текущего пользователя и временными метками.

#### Scenario: Создание root-страницы
- **WHEN** аутентифицированный пользователь отправляет `POST /api/v1/pages` с идентификатором своего проекта и без идентификатора родителя
- **THEN** API отвечает `201` и возвращает страницу без родителя, принадлежащую этому пользователю и этому проекту
- **AND** страница появляется последней среди root-страниц дерева этого проекта

#### Scenario: Создание дочерней страницы
- **WHEN** пользователь отправляет `POST /api/v1/pages` с идентификатором своей существующей страницы в качестве родителя и проектом этого родителя
- **THEN** API отвечает `201`, возвращает страницу с этим родителем, тем же владельцем и тем же проектом
- **AND** страница появляется последней среди детей этого родителя

#### Scenario: Создание дочерней страницы редактором
- **GIVEN** пользователю выдан `editor` на чужой странице
- **WHEN** он создаёт под ней дочернюю страницу, указывая проект этой страницы
- **THEN** API отвечает `201`, владельцем созданной страницы становится владелец родителя, а создателем — актор
- **AND** созданная страница появляется в дереве владельца и в выдаче доступных страниц актора

#### Scenario: Создание дочерней страницы читателем
- **GIVEN** пользователю выдан `viewer` на чужой странице
- **WHEN** он пытается создать под ней дочернюю страницу
- **THEN** API отвечает `403` в едином формате HTTP-ошибок и не создаёт страницу

#### Scenario: Создание в чужом проекте
- **WHEN** пользователь указывает проект, принадлежащий другому пользователю, не указывая родителя
- **THEN** API отвечает `404` в едином формате HTTP-ошибок и не создаёт страницу

#### Scenario: Создание в несуществующем проекте
- **WHEN** пользователь указывает идентификатор проекта, которому не соответствует ни один проект
- **THEN** API отвечает `404` с тем же статусом и тем же телом, что и при чужом проекте

#### Scenario: Проект запроса не совпадает с проектом родителя
- **WHEN** пользователь указывает доступного ему родителя и проект, отличный от проекта этого родителя
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не создаёт страницу

#### Scenario: Создание страницы без заголовка
- **WHEN** запрос не содержит заголовок
- **THEN** API отвечает `201` и создаёт страницу с пустым заголовком, а не отклоняет запрос

#### Scenario: Создание с родителем из чужого дерева
- **WHEN** пользователь указывает родителем страницу, на которую ему ничего не выдано
- **THEN** API отвечает `404` в едином формате HTTP-ошибок и не создаёт страницу

#### Scenario: Создание с несуществующим родителем
- **WHEN** пользователь указывает родителем идентификатор, которому не соответствует ни одна страница
- **THEN** API отвечает `404` с тем же статусом и тем же телом, что и при родителе, на которого ничего не выдано

#### Scenario: Создание с недопустимыми данными
- **WHEN** запрос не содержит идентификатор проекта, содержит идентификатор проекта или родителя не в формате UUID, заголовок длиннее допустимого либо лишнее поле
- **THEN** API отвечает `400` в едином формате HTTP-ошибок с перечнем validation messages и не создаёт страницу

#### Scenario: Создание без аутентификации
- **WHEN** запрос не содержит действующий access-токен
- **THEN** API отвечает `401` в едином формате HTTP-ошибок и не создаёт страницу

### Requirement: Чтение одной страницы
API MUST публиковать защищённый `GET /api/v1/pages/{pageId}`, возвращающий одну страницу, к которой у текущего пользователя есть эффективный доступ. Роли `viewer` MUST хватать: чтение — минимальное, что даёт любое разрешение.

#### Scenario: Чтение своей страницы
- **WHEN** пользователь запрашивает страницу своего дерева
- **THEN** API отвечает `200` и возвращает её идентификатор, проект, родителя, заголовок, ранг, режим наследования, эффективную роль `owner` и временные метки

#### Scenario: Чтение страницы по прямому разрешению
- **GIVEN** пользователю выдан `viewer` на чужой странице
- **WHEN** он запрашивает эту страницу
- **THEN** API отвечает `200` и возвращает её с эффективной ролью `viewer`

#### Scenario: Чтение страницы по унаследованному разрешению
- **GIVEN** пользователю выдан `editor` на чужой странице, а запрашиваемая страница — её потомок в режиме `inherit`
- **WHEN** он запрашивает этого потомка
- **THEN** API отвечает `200` и возвращает его с эффективной ролью `editor`

#### Scenario: Чтение страницы за границей restricted
- **GIVEN** пользователю выдан `editor` на чужой странице, а запрашиваемый потомок имеет режим `restricted` и собственного разрешения ему не выдано
- **THEN** API отвечает `404` в едином формате HTTP-ошибок

#### Scenario: Чтение чужой страницы
- **WHEN** пользователь запрашивает страницу, на которую ему ничего не выдано
- **THEN** API отвечает `404` в едином формате HTTP-ошибок

#### Scenario: Чтение несуществующей страницы
- **WHEN** пользователь запрашивает идентификатор, которому не соответствует ни одна страница
- **THEN** API отвечает `404` с тем же статусом и тем же телом, что и при странице, на которую ничего не выдано

### Requirement: Переименование страницы
API MUST публиковать защищённый `PATCH /api/v1/pages/{pageId}`, изменяющий заголовок страницы. Переименование MUST требовать роли `editor` или выше: заголовок — часть содержимого страницы, а не структуры дерева. Роли `viewer` MUST NOT хватать.

Переименование MUST NOT изменять владельца, родителя, ранг, режим наследования, прямые разрешения и состав дерева.

Запрос MUST NOT позволять изменить владельца, проект, родителя, ранг, создателя, режим наследования, роль или отметку удаления.

#### Scenario: Успешное переименование
- **WHEN** пользователь отправляет `PATCH /api/v1/pages/{pageId}` со своим идентификатором страницы и новым заголовком
- **THEN** API отвечает `200`, возвращает страницу с новым заголовком и обновлённой меткой изменения
- **AND** родитель, ранг и владелец страницы остаются прежними

#### Scenario: Переименование редактором
- **GIVEN** пользователю выдан `editor` на чужой странице
- **WHEN** он переименовывает её
- **THEN** API отвечает `200`, заголовок меняется, а владелец страницы остаётся прежним

#### Scenario: Переименование читателем
- **GIVEN** пользователю выдан `viewer` на чужой странице
- **WHEN** он пытается её переименовать
- **THEN** API отвечает `403` в едином формате HTTP-ошибок и не изменяет страницу

#### Scenario: Переименование чужой страницы
- **WHEN** пользователь переименовывает страницу, на которую ему ничего не выдано
- **THEN** API отвечает `404` в едином формате HTTP-ошибок и не изменяет страницу

#### Scenario: Попытка изменить структурные поля переименованием
- **WHEN** запрос переименования содержит идентификатор владельца, проекта, родителя, ранг, режим наследования или отметку удаления
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не изменяет страницу

### Requirement: Перемещение поддерева и упорядочивание
API MUST публиковать защищённый `POST /api/v1/pages/{pageId}/move`, задающий нового родителя страницы и её место среди братьев. Пустой родитель MUST означать перенос страницы в корень дерева. Место среди братьев MUST задаваться соседями — страницей, после которой и страницей, перед которой должна оказаться перемещаемая; при отсутствии обоих соседей страница MUST становиться последней среди братьев. Клиент MUST NOT передавать ранг напрямую.

Перемещение MUST требовать роли `owner` на перемещаемой странице, на её текущем родителе и на новом родителе. Перемещение меняет границы наследования сразу для трёх поддеревьев, и делать это MUST быть вправе только владелец дерева: `editor` MUST получать `403`, потому что перемещаемую страницу он видит.

Перемещение MUST переносить всё поддерево: потомки перемещаемой страницы MUST сохранять своих родителей и свой относительный порядок.

Смена родителя и вычисление нового ранга MUST выполняться в одной транзакции. При отказе на любом шаге дерево MUST оставаться в состоянии, предшествовавшем запросу: ни родитель, ни ранг, ни какая-либо другая страница MUST NOT остаться изменёнными.

Перемещение MUST NOT изменять ни владельца, ни проект, ни режим наследования, ни прямые разрешения перемещаемой страницы и её потомков. Новый родитель MUST лежать в том же проекте, что и перемещаемая страница. Соседи MUST принадлежать тому же родителю, в который выполняется перенос. Соседи MUST задавать существующую щель: один и тот же идентификатор с обеих сторон, обратный порядок и пара, между которой стоит ещё один брат, MUST отклоняться. Сама перемещаемая страница MUST NOT считаться помехой между своими будущими соседями.

#### Scenario: Перемещение под другого родителя
- **WHEN** пользователь перемещает страницу под другую свою страницу
- **THEN** API отвечает `200`, страница появляется среди детей нового родителя и исчезает из прежнего уровня
- **AND** её потомки остаются её потомками в прежнем относительном порядке

#### Scenario: Перемещение в корень
- **WHEN** пользователь перемещает дочернюю страницу, не указывая родителя
- **THEN** API отвечает `200` и страница становится root-страницей дерева своего проекта
- **AND** её проект не изменяется

#### Scenario: Изменение позиции среди братьев
- **WHEN** пользователь перемещает страницу между двумя её соседями по тому же родителю
- **THEN** API отвечает `200` и последующее чтение дерева возвращает её ровно между указанными соседями
- **AND** ранги остальных братьев не изменяются

#### Scenario: Перемещение в конец уровня
- **WHEN** пользователь перемещает страницу, указывая нового родителя и не указывая ни одного соседа
- **THEN** страница становится последней среди детей этого родителя

#### Scenario: Перемещение редактором
- **GIVEN** пользователю выдан `editor` на чужой странице и на целевом родителе
- **WHEN** он пытается переместить эту страницу
- **THEN** API отвечает `403` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Перемещение в саму себя
- **WHEN** пользователь указывает перемещаемую страницу её собственным родителем
- **THEN** API отвечает `409` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Перемещение в собственного потомка
- **WHEN** пользователь указывает новым родителем страницу, являющуюся потомком перемещаемой на любой глубине
- **THEN** API отвечает `409` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Перемещение под родителя из чужого дерева
- **WHEN** пользователь указывает новым родителем страницу, на которую ему ничего не выдано
- **THEN** API отвечает `404` в едином формате HTTP-ошибок, дерево не изменяется, и владелец перемещаемой страницы остаётся прежним

#### Scenario: Перемещение под родителя из другого проекта
- **WHEN** пользователь указывает новым родителем свою страницу, лежащую в другом его проекте
- **THEN** API отвечает `400` в едином формате HTTP-ошибок, дерево не изменяется, и проект перемещаемой страницы остаётся прежним

#### Scenario: Перемещение чужой страницы
- **WHEN** пользователь перемещает страницу, на которую ему ничего не выдано
- **THEN** API отвечает `404` с тем же статусом и тем же телом, что и при перемещении несуществующей страницы

#### Scenario: Сосед из другого уровня
- **WHEN** указанный сосед существует и доступен пользователю, но принадлежит не тому родителю, в который выполняется перенос
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Противоречивая пара соседей
- **WHEN** оба соседа заданы одним и тем же идентификатором либо «предыдущий» лежит среди братьев не раньше «следующего»
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Соседи не смежны
- **GIVEN** на целевом уровне между двумя братьями стоит третий
- **WHEN** пользователь указывает этих двух братьев соседями перемещаемой страницы
- **THEN** API отвечает `400` в едином формате HTTP-ошибок и не изменяет дерево

#### Scenario: Перемещение между собственными соседями
- **GIVEN** перемещаемая страница уже стоит между двумя братьями того же уровня
- **WHEN** пользователь указывает этих братьев её соседями
- **THEN** API отвечает `200`: сама перемещаемая страница помехой не считается

#### Scenario: Несуществующий сосед
- **WHEN** указанный сосед не существует либо недоступен пользователю
- **THEN** API отвечает `404` и не изменяет дерево

#### Scenario: Отказ в середине перемещения
- **WHEN** перемещение прерывается ошибкой после смены родителя, но до сохранения нового ранга
- **THEN** ни смена родителя, ни изменение ранга не сохраняются, и дерево остаётся в исходном состоянии

### Requirement: Мягкое удаление страницы
API MUST публиковать защищённый `DELETE /api/v1/pages/{pageId}`, помечающий страницу удалённой. Удаление MUST быть мягким: запись MUST оставаться в хранилище, и её идентификатор, владелец, проект, родитель, заголовок, ранг, режим наследования и прямые разрешения MUST оставаться неизменными.

Удаление MUST требовать роли `owner`. Удаление уносит в корзину владельца всё поддерево, и делать это MUST быть вправе только он: `editor` MUST получать `403`, потому что удаляемую страницу он видит.

Удаление MUST каскадно помечать всё живое поддерево удаляемой страницы на любой глубине. Пометка страницы и пометка её поддерева MUST выполняться в одной транзакции: при отказе на любом шаге ни одна страница MUST NOT остаться помеченной.

Успешное удаление MUST отвечать `204` без тела. Удаление уже удалённой или несуществующей страницы, а равно страницы, на которую текущему пользователю ничего не выдано, MUST отвечать `404` в едином формате HTTP-ошибок.

#### Scenario: Удаление страницы без потомков
- **WHEN** пользователь отправляет `DELETE /api/v1/pages/{pageId}` со своей страницей без потомков
- **THEN** API отвечает `204`
- **AND** последующие `GET /api/v1/pages` и `GET /api/v1/pages/{pageId}` эту страницу не возвращают

#### Scenario: Каскадное удаление поддерева
- **GIVEN** страница с детьми и внуками
- **WHEN** пользователь удаляет эту страницу
- **THEN** API отвечает `204`, и ни она, ни один её потомок не возвращаются чтением дерева и чтением одной страницы

#### Scenario: Соседнее поддерево не затрагивается
- **WHEN** пользователь удаляет одну из двух своих root-страниц
- **THEN** вторая root-страница и все её потомки остаются в выдаче дерева, и их ранги не изменяются

#### Scenario: Удаление редактором
- **GIVEN** пользователю выдан `editor` на чужой странице
- **WHEN** он пытается её удалить
- **THEN** API отвечает `403` в едином формате HTTP-ошибок, и страница остаётся в дереве владельца

#### Scenario: Повторное удаление
- **WHEN** пользователь удаляет страницу, уже помеченную удалённой
- **THEN** API отвечает `404` с тем же статусом и тем же телом, что и при удалении несуществующей страницы

#### Scenario: Удаление чужой страницы
- **WHEN** пользователь удаляет страницу, на которую ему ничего не выдано
- **THEN** API отвечает `404` в едином формате HTTP-ошибок, и страница остаётся неудалённой

#### Scenario: Удаление без аутентификации
- **WHEN** запрос не содержит действующий access-токен
- **THEN** API отвечает `401` в едином формате HTTP-ошибок и не удаляет страницу

#### Scenario: Отказ в середине каскада
- **WHEN** удаление прерывается ошибкой после пометки части поддерева
- **THEN** ни одна страница не остаётся помеченной, и дерево возвращается чтением в прежнем виде

### Requirement: Документирование операций страниц в OpenAPI
Опубликованный OpenAPI-документ MUST описывать каждую операцию над страницами со стабильным явным operation ID, schema тела запроса, schema успешного ответа и документированными ответами `400`, `401`, `404`, а для операций, требующих роли выше `viewer`, — дополнительно `403`. Для перемещения, восстановления и окончательного удаления одной страницы MUST документироваться `409`. Операции мягкого удаления, окончательного удаления и очистки корзины MUST документировать ответ `204` без тела, а окончательное удаление — ещё и параметр подтверждения. Schema страницы MUST описывать режим наследования доступа и эффективную роль текущего пользователя как перечисления с явными значениями. Каждая операция MUST быть помечена bearer-схемой безопасности. Закоммиченный OpenAPI snapshot и сгенерированный из него frontend-код MUST соответствовать этим операциям.

#### Scenario: Операции страниц в OpenAPI-документе
- **WHEN** клиент читает опубликованный OpenAPI JSON
- **THEN** документ содержит paths операций страниц с явными operation ID, schemas запросов и ответов и bearer-схемой безопасности

#### Scenario: Ответ о недостаточной роли в OpenAPI-документе
- **WHEN** клиент читает описание создания, переименования, перемещения или удаления страницы
- **THEN** среди документированных ответов есть `403` в едином формате HTTP-ошибок

#### Scenario: Операции корзины в OpenAPI-документе
- **WHEN** клиент читает опубликованный OpenAPI JSON
- **THEN** документ содержит операции мягкого удаления, восстановления, чтения корзины, окончательного удаления страницы и очистки корзины страниц с явными operation ID и документированными ответами

#### Scenario: Отсутствие contract drift
- **WHEN** выполняется обязательная проверка соответствия сгенерированных артефактов
- **THEN** закоммиченные `openapi.json` и сгенерированный web-код совпадают с текущей Nest metadata

## REMOVED Requirements

### Requirement: Изоляция дерева по владельцу
**Reason**: Изоляция перестаёт опираться на владельца: страница доступна и по прямому, и по унаследованному разрешению, а полный запрет `403` больше не выполним — читатель, которому не хватает роли, обязан получить внятный отказ, а не `404` на странице, которую он видит.

**Migration**: Заменено требованием «Изоляция дерева по доступу» той же capability. Правило неразличимости недоступного и несуществующего сохранено дословно; добавлен единственный разрешённый случай `403` — недостаточная роль на видимой актору странице.
