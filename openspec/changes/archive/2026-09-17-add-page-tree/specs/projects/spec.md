## Purpose

Определяет наблюдаемый контракт проектов Lite Notion: контейнеров верхнего уровня, которым принадлежат деревья страниц. Проект нужен странице обязательно, поэтому capability покрывает создание проекта, перечисление проектов владельца и изоляцию чужих проектов.

## ADDED Requirements

### Requirement: Проект как контейнер владельца
Проект MUST принадлежать ровно одному пользователю-владельцу и MUST иметь имя. Владельцем создаваемого проекта MUST становиться текущий пользователь; идентификатор владельца MUST NOT приниматься от клиента.

Проект MUST быть контейнером для страниц: страница MUST принадлежать ровно одному проекту, и владелец страницы и владелец её проекта MUST совпадать. Это совпадение MUST быть закреплено на уровне базы данных, а не только проверкой в приложении.

#### Scenario: Владелец созданного проекта
- **GIVEN** аутентифицированный пользователь
- **WHEN** он создаёт проект
- **THEN** созданный проект принадлежит ему

#### Scenario: Разные владельцы у страницы и её проекта отвергаются базой
- **WHEN** предпринимается попытка сохранить страницу, чей идентификатор владельца не совпадает с идентификатором владельца её проекта, в обход прикладных проверок
- **THEN** база данных отклоняет запись нарушением constraint, и страница не появляется

### Requirement: Создание проекта
API MUST публиковать защищённый `POST /api/v1/projects`, принимающий имя проекта. Имя MUST быть непустым и не длиннее установленного предела. Успешное создание MUST отвечать `201` и возвращать проект с его идентификатором, владельцем и именем.

Одинаковые имена у разных проектов одного владельца MUST быть допустимы: имя не является идентификатором.

#### Scenario: Успешное создание проекта
- **WHEN** аутентифицированный пользователь отправляет `POST /api/v1/projects` с непустым именем
- **THEN** API отвечает `201` и возвращает проект, принадлежащий этому пользователю

#### Scenario: Создание проекта с занятым именем
- **WHEN** пользователь создаёт второй проект с именем уже существующего своего проекта
- **THEN** API отвечает `201` и создаёт второй проект

#### Scenario: Создание проекта с недопустимым именем
- **WHEN** запрос содержит пустое имя, имя длиннее допустимого либо лишнее поле
- **THEN** API отвечает `400` в едином формате HTTP-ошибок с перечнем validation messages и не создаёт проект

#### Scenario: Создание проекта без аутентификации
- **WHEN** запрос не содержит действующий access-токен
- **THEN** API отвечает `401` в едином формате HTTP-ошибок и не создаёт проект

### Requirement: Список проектов владельца
API MUST публиковать защищённый `GET /api/v1/projects`, возвращающий проекты текущего пользователя и только их. Порядок MUST быть детерминированным: два последовательных чтения без изменяющих операций MUST возвращать одинаковую последовательность.

Пользователь без проектов MUST получать пустой список, а не ошибку.

#### Scenario: Чтение непустого списка проектов
- **WHEN** пользователь с несколькими проектами запрашивает `GET /api/v1/projects`
- **THEN** API отвечает `200` и возвращает его проекты
- **AND** ответ не содержит ни одного проекта другого пользователя

#### Scenario: Чтение пустого списка проектов
- **WHEN** пользователь, не создавший ни одного проекта, запрашивает `GET /api/v1/projects`
- **THEN** API отвечает `200` и возвращает пустой список

#### Scenario: Детерминированный порядок проектов
- **WHEN** пользователь дважды подряд запрашивает список, не выполняя между запросами изменяющих операций
- **THEN** порядок проектов в обоих ответах совпадает

### Requirement: Изоляция проектов по владельцу
Ни одна операция MUST NOT раскрывать существование проекта другого пользователя. Для чужого и для несуществующего проекта API MUST отвечать одинаковым HTTP status `404` и одинаковым телом ответа. Ответ `403` MUST NOT использоваться.

Ни одна операция MUST NOT изменять владельца существующего проекта.

#### Scenario: Использование чужого проекта
- **WHEN** пользователь адресует проект другого пользователя в любой операции, принимающей идентификатор проекта
- **THEN** API отвечает `404` в едином формате HTTP-ошибок

#### Scenario: Чужой и несуществующий проект неразличимы
- **WHEN** пользователь адресует чужой проект и затем идентификатор, которому не соответствует ни один проект
- **THEN** оба ответа имеют одинаковый статус `404` и одинаковое тело

### Requirement: Документирование операций проектов в OpenAPI
Опубликованный OpenAPI-документ MUST описывать каждую операцию над проектами со стабильным явным operation ID, schema тела запроса, schema успешного ответа и документированными ответами `400` и `401`. Каждая операция MUST быть помечена bearer-схемой безопасности.

#### Scenario: Операции проектов в OpenAPI-документе
- **WHEN** клиент читает опубликованный OpenAPI JSON
- **THEN** документ содержит paths операций проектов с явными operation ID, schemas запросов и ответов и bearer-схемой безопасности
