## Purpose

Даёт владельцу возможность просматривать удалённые страницы и проекты, восстанавливать их и управлять безвозвратным удалением через защищённый интерфейс приложения.

## ADDED Requirements

### Requirement: Защищённый экран корзины
Система SHALL предоставлять экран корзины по маршруту `/trash` внутри авторизованной части приложения и переход к нему из существующей навигации. Экран SHALL содержать отдельные вкладки «Страницы» и «Проекты».

#### Scenario: Переход в корзину
- **WHEN** авторизованный пользователь выбирает пункт корзины в навигации
- **THEN** приложение открывает `/trash` и показывает вкладку страниц

#### Scenario: Прямой переход без авторизации
- **WHEN** неавторизованный пользователь открывает `/trash`
- **THEN** срабатывает существующий сценарий защиты приватных маршрутов
- **AND** данные корзины не отображаются

#### Scenario: Переключение вкладки
- **WHEN** пользователь выбирает вкладку «Проекты» или «Страницы»
- **THEN** экран показывает соответствующий список и доступные для него действия

### Requirement: Просмотр удалённых страниц и проектов
Вкладка страниц SHALL показывать все удалённые страницы текущего владельца с названием, датой удаления и вложенностью, возвращённой API. Если название исходного проекта удаётся сопоставить по `projectId` с активным или удалённым проектом, UI SHALL показать это название; если сопоставление невозможно, UI SHALL показать безопасный fallback и оставить страницу доступной. Вкладка проектов SHALL показывать имя и дату удаления проекта. Страница, удалённая вместе с проектом, SHALL оставаться видимой только во вкладке страниц.

#### Scenario: Просмотр дерева страниц
- **GIVEN** в корзине есть удалённая страница с удалёнными потомками
- **WHEN** пользователь открывает вкладку «Страницы»
- **THEN** страница отображается с датой удаления и соответствующей вложенностью
- **AND** для страницы показано имя её исходного проекта

#### Scenario: Просмотр страниц удалённого проекта
- **GIVEN** проект с страницами удалён вместе с проектом
- **WHEN** пользователь открывает корзину
- **THEN** страницы проекта показаны во вкладке «Страницы» с сохранённой вложенностью
- **AND** проект показан во вкладке «Проекты» без дублирования списка страниц

#### Scenario: Исходный проект страницы активен
- **GIVEN** исходный проект удалённой страницы присутствует в списке активных проектов
- **WHEN** пользователь просматривает страницу в корзине
- **THEN** UI показывает название активного проекта

#### Scenario: Исходный проект страницы находится в корзине
- **GIVEN** исходный проект удалённой страницы присутствует в списке удалённых проектов
- **WHEN** пользователь просматривает страницу в корзине
- **THEN** UI показывает название удалённого проекта

#### Scenario: Название исходного проекта не определено
- **GIVEN** `projectId` удалённой страницы нельзя сопоставить с активным или удалённым проектом
- **WHEN** пользователь просматривает страницу в корзине
- **THEN** UI показывает безопасное fallback-значение вместо названия
- **AND** страница и её действия остаются доступными

#### Scenario: Пустая корзина
- **WHEN** выбранная вкладка не содержит удалённых элементов
- **THEN** экран показывает понятное пустое состояние для этой вкладки

#### Scenario: Загрузка или ошибка чтения
- **WHEN** данные выбранной вкладки загружаются или запрос завершается ошибкой
- **THEN** экран показывает доступное состояние загрузки или ошибку с возможностью повторить запрос
- **AND** ошибка одной вкладки не маскируется пустым списком другой вкладки

### Requirement: Восстановление элементов корзины
Система SHALL позволять владельцу восстановить каждый отображаемый узел страницы отдельно или восстановить проект. После успешного восстановления выбранный узел SHALL исчезать из соответствующей корзины, обе корзины и обычные деревья страниц/список проектов SHALL обновляться без перезагрузки страницы.

Восстановление страницы SHALL сохранять существующую семантику API: восстановление предка не восстанавливает независимо удалённые страницы-потомки; если прежний родитель уже удалён, восстановленная страница становится корнем; если исходный проект удалён, пользователь выбирает активный целевой проект. Восстановление проекта SHALL восстанавливать только страницы, помеченные удалением этого проекта, сохраняя страницы, ранее удалённые самостоятельно.

#### Scenario: Восстановление страницы с сохранением независимо удалённого потомка
- **GIVEN** потомок был удалён самостоятельно, затем удалён его предок
- **WHEN** пользователь восстанавливает предка
- **THEN** предок и страницы, удалённые только вместе с ним, возвращаются в дерево
- **AND** самостоятельно удалённый потомок остаётся в корзине

#### Scenario: Восстановление страницы с удалённым родителем
- **GIVEN** выбранная страница удалена, а её прежний родитель остаётся в корзине
- **WHEN** пользователь успешно восстанавливает выбранную страницу
- **THEN** страница становится корнем своего активного проекта
- **AND** другие узлы корзины, включая бывших соседей, остаются в корзине

#### Scenario: Восстановление вложенного узла, пока родитель остаётся удалённым
- **GIVEN** выбранный вложенный узел и его потомки удалены, а его прежний родитель остаётся в корзине
- **WHEN** пользователь восстанавливает именно вложенный узел
- **THEN** выбранный узел восстанавливается корнем активного проекта
- **AND** его потомки, удалённые вместе с ним, также восстанавливаются
- **AND** его самостоятельно удалённые потомки и прежний родитель остаются в корзине

#### Scenario: Восстановление страницы из удалённого проекта
- **GIVEN** исходный проект страницы удалён
- **WHEN** пользователь выбирает восстановление страницы
- **THEN** интерфейс предлагает выбрать активный целевой проект
- **AND** отправляет восстановление только после выбора проекта
- **AND** после успеха страница становится корнем целевого проекта

#### Scenario: Нет активного проекта назначения
- **GIVEN** исходный проект страницы удалён и у владельца нет активных проектов
- **WHEN** пользователь начинает восстановление страницы
- **THEN** UI объясняет, что сначала нужен активный проект назначения
- **AND** запрос восстановления не отправляется
- **AND** страница остаётся в корзине

#### Scenario: Восстановление проекта с отдельно удалёнными страницами
- **GIVEN** проект удалён после того, как одна из его страниц была удалена самостоятельно
- **WHEN** пользователь восстанавливает проект
- **THEN** проект и страницы, удалённые вместе с ним, возвращаются
- **AND** самостоятельно удалённая страница остаётся в корзине страниц

#### Scenario: Устаревшее или конкурентное восстановление
- **WHEN** элемент уже восстановлен, безвозвратно удалён или операция отклонена из-за текущего состояния
- **THEN** интерфейс показывает ошибку операции и обновляет затронутые списки и дерево
- **AND** не показывает устаревшее состояние как успешно восстановленное

#### Scenario: Состояние операции восстановления
- **WHEN** запрос восстановления выполняется или завершается ошибкой
- **THEN** повторный запрос для того же элемента недоступен до завершения текущего
- **AND** после ошибки пользователь получает доступное сообщение и может повторить действие

### Requirement: Подтверждение безвозвратного удаления
Система SHALL предоставлять действие permanent delete для каждого отображаемого узла страницы и проекта. Purge страницы физически затрагивает выбранный узел и его потомков; purge проекта затрагивает выбранный проект и содержащиеся в нём страницы. Система SHALL требовать явного подтверждения с названием выбранного элемента и описанием такого охвата перед отправкой destructive-запроса. До подтверждения запрос SHALL NOT отправляться. После успешного purge обе корзины, обычное дерево страниц и список проектов SHALL обновляться без перезагрузки страницы. Пока запрос выполняется, повторная отправка и закрытие подтверждения SHALL быть недоступны; ошибка SHALL оставлять подтверждение открытым и позволять повторить действие.

#### Scenario: Отмена необратимого действия
- **WHEN** пользователь закрывает подтверждение до отправки запроса
- **THEN** безвозвратное удаление не выполняется
- **AND** элемент остаётся в корзине

#### Scenario: Повторная отправка заблокирована
- **WHEN** запрос безвозвратного удаления находится в состоянии выполнения
- **THEN** повторное подтверждение невозможно
- **AND** подтверждение показывает состояние выполнения и не закрывается до ответа

#### Scenario: Ошибка необратимого действия
- **WHEN** запрос удаления завершается ошибкой, отличной от подтверждаемого каскадного конфликта
- **THEN** подтверждение остаётся открытым, элемент остаётся видимым до обновления данных, и показывается доступная ошибка

### Requirement: Явное подтверждение каскадного purge
Для безвозвратного удаления отдельной страницы или проекта интерфейс SHALL сначала отправлять запрос без `cascade=true`. При ответе `409` с перечнем других элементов корзины, затрагиваемых удалением, интерфейс SHALL показать этот перечень и запросить новое явное подтверждение. Только после него SHALL повторить тот же запрос с `cascade=true`. Закрытие второго подтверждения SHALL NOT отправлять каскадный запрос.

Интерфейс SHALL считать `409` подтверждаемым каскадным конфликтом только если `error.status === 409` и `error.info.message` является массивом минимум из двух строк, каждая строка имеет тип string, а первая строка непустая. Первый элемент SHALL показываться как служебное пояснение, остальные — как названия затрагиваемых страниц; пустое название страницы SHALL сохраняться как получено. Если status или структура ответа не распознаны, интерфейс SHALL показать обычную ошибку и SHALL NOT отправлять `cascade=true`.

#### Scenario: Сервер сообщает о затрагиваемых страницах
- **GIVEN** purge страницы или проекта затронет независимо удалённые страницы
- **WHEN** начальный запрос без `cascade=true` возвращает `409`
- **THEN** интерфейс показывает имена страниц из ответа сервера
- **AND** запрашивает отдельное подтверждение их безвозвратного удаления
- **AND** показывает первую строку `message` отдельно как пояснение, а последующие строки — как названия

#### Scenario: Некорректный ответ 409
- **GIVEN** индивидуальный purge получает статус 409, но `error.info.message` отсутствует, не является массивом строк, содержит только пояснение или первая строка пуста
- **WHEN** UI обрабатывает ошибку
- **THEN** UI показывает обычную ошибку и обновляет актуальное состояние
- **AND** каскадный запрос с `cascade=true` не отправляется

#### Scenario: Permanent delete вложенного узла
- **GIVEN** выбран вложенный узел, у которого есть потомки и отдельно удалённый потомок
- **WHEN** пользователь подтверждает permanent delete этого узла
- **THEN** удаляются выбранный узел и его физическое поддерево
- **AND** при `409` UI отдельно показывает самостоятельно удалённые страницы, которых также затронет cascade
- **AND** родитель выбранного узла, соседние ветви и элементы вне поддерева остаются нетронутыми

#### Scenario: Каскад выполняется только после второго подтверждения
- **GIVEN** пользователь получил `409` и видит перечень затрагиваемых элементов
- **WHEN** пользователь подтверждает каскад
- **THEN** интерфейс повторяет исходный purge с `cascade=true`
- **WHEN** пользователь отменяет или закрывает второе подтверждение
- **THEN** запрос с `cascade=true` не отправляется

#### Scenario: Конкурентное изменение при purge
- **WHEN** выбранная страница или проект изменили состояние после показа корзины, и individual purge получает ошибку или `404`
- **THEN** интерфейс сообщает, что операция не выполнена, и обновляет списки корзины и обычные деревья
- **AND** повторная попытка не включает `cascade=true` без нового явного подтверждения

### Requirement: Доступ к корзине ограничен владельцем
Экран и операции корзины SHALL работать только с данными текущего владельца. Страницы, к которым пользователь имеет только viewer/editor access, SHALL NOT появляться в его корзине как принадлежащие ему элементы и SHALL NOT восстанавливаться или безвозвратно удаляться этим пользователем.

#### Scenario: Доступная пользователю чужая страница
- **GIVEN** пользователь имеет viewer или editor access к странице другого владельца
- **WHEN** он открывает свою корзину
- **THEN** чужая страница не появляется в его списке корзины

#### Scenario: Операция над чужим элементом
- **WHEN** пользователь пытается восстановить или удалить чужую страницу либо проект
- **THEN** операция завершается отказом существующего owner-scoped API
- **AND** чужой элемент и дерево пользователя не изменяются

### Requirement: Удаление страницы во время совместного редактирования
После soft delete страницы совместный редактор SHALL прекратить сохранять изменения в удалённую страницу. При отказе сохранения удалённой страницы collaboration room SHALL закрыться согласно существующему lifecycle. Пользовательский интерфейс корзины SHALL обновлять обычное дерево и список корзины после подтверждённого удаления без перезагрузки.

#### Scenario: Редактор уже подключён к удаляемой странице
- **GIVEN** несколько редакторов подключены к странице через Yjs/Hocuspocus
- **WHEN** владелец удаляет страницу
- **THEN** сервер не сохраняет изменения в удалённую страницу
- **AND** комната закрывается при отказе сохранения по существующему collaboration lifecycle

#### Scenario: Удаление открытой у владельца страницы
- **GIVEN** удаляемая страница открыта у владельца
- **WHEN** владелец подтверждает soft delete
- **THEN** страница исчезает из обычного дерева и появляется в корзине без reload
- **AND** навигация больше не оставляет пользователя на недоступной странице

### Requirement: Актуальность корзины после soft delete проекта
После существующего soft delete mutation проекта UI SHALL обновить обе корзины и список проектов без перезагрузки. Страницы проекта SHALL оставаться доступными во вкладке страниц, а удалённый проект SHALL появиться во вкладке проектов.

#### Scenario: Проект удалён из текущего списка
- **GIVEN** владелец удаляет проект, содержащий страницы
- **WHEN** существующая soft delete mutation проекта завершается успешно
- **THEN** проект исчезает из активного списка проектов и появляется во вкладке «Проекты» корзины
- **AND** его удалённые страницы отображаются во вкладке «Страницы» с исходным проектом и вложенностью
- **AND** обе вкладки показывают актуальные данные без перезагрузки
